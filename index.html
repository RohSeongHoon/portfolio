AI 개인화 추천 서버

서버는 혼자 설계하고 구현했으며, 추천 알고리즘 연구는 연구원과 공동으로 진행했습니다.

SNS 피드와 커머스 상품을 위한 개인화 추천 서버입니다. 커머스 상품 추천은 이후 별도 서비스로 분리했습니다. 관심사, 인기, 최신, 팔로우, 카테고리를 각각 후보 채널로 두고, 화면마다 다른 기준으로 순위를 정합니다. 사용자 상태는 사람이 직접 읽고 해석할 수 있는 지표로 저장했습니다.

기간별 사용자 상태

사용자 상태는 현재 세션, 최근 7일, 최근 30일로 나눠 관리했습니다. 현재 보고 있는 콘텐츠는 추천에 바로 반영하고, 클릭 한 번으로 장기 취향이 바뀌지 않도록 했습니다. 이 상태 계산은 이후 행동 분석 서버로 옮겼습니다.

한 일

  • 코드를 역할에 따라 5계층 클린 아키텍처로 나누고, 새 추천 채널은 레지스트리에 등록만 하면 추가되도록 만들었습니다.
  • 개인정보 삭제 요청이 들어오면 관련 저장소 12곳의 데이터를 삭제하고, 필수 작업이 하나라도 실패하면 성공 응답을 보내지 않도록 구현했습니다. 광고 정책과 민감정보 사용 제한을 검사하는 규칙도 추가했습니다.

문제 해결

새로고침할 때마다 피드가 바뀌던 문제

  1. 증상같은 사용자로 세 번 호출했을 때 세 결과가 모두 같은 경우가 8.3%뿐이었습니다.
  2. 원인처음에는 시간 기반 랭킹을 의심해 시각을 고정하고 다시 측정했지만 일치율이 그대로였습니다. 실제 원인은 탐색 알고리즘에 난수 시드가 전달되지 않는 문제였습니다.
  3. 조치탐색 기능은 유지하면서 시드를 사용자와 시간대 기준으로 정하도록 바꾸고, 시드가 빠지거나 상수로 고정되면 실패하는 테스트를 추가했습니다. 그 결과 일치율이 93.3%로 올랐습니다.

서버 시작 직후 첫 응답이 빈 피드로 나가던 문제

  1. 증상서버 시작 후 첫 추천 요청이 30초 넘게 걸리고 빈 피드를 반환했습니다. 두 번째 요청부터는 정상이어서 개발 중에는 잘 드러나지 않았습니다.
  2. 원인텍스트 인코더를 첫 호출 때 불러오는데, 불러오는 시간이 채널 시간 제한보다 길었습니다. 채널 격리는 설계대로 동작했기 때문에 빈 결과가 정상 응답으로 반환됐습니다.
  3. 조치서버가 시작될 때 별도 스레드에서 인코더를 미리 불러오고, 실패하면 그 기능만 끈 채 서버를 시작하도록 했습니다. 제어는 새 플래그 대신 기존 기능 플래그를 사용했고, 첫 응답 시간은 0.58초로 줄었습니다.

배포 전에 발견한 개인화 회귀

  1. 상황배포 전인 벡터 저장소 구조 변경 작업에서 개인화 추천이 동작하지 않았습니다. 에러나 로그는 남지 않았습니다.
  2. 원인검색 코드만 새 구조로 바꾸고 벡터를 다시 읽는 코드는 이전 형식을 그대로 사용해, 관심사 벡터가 비어 있었습니다.

SNS의 콘텐츠 이용 기록과 쇼핑 서비스의 상품 탐색 기록을 같은 기준으로 분석해, 관심사나 구매 의도 같은 사용자 상태를 추정하는 서버입니다. 추천 서버에 있던 상태 계산 기능을 별도 서버로 분리했습니다. 사용자의 심리를 직접 측정하지 않고 행동 기록만으로 추정합니다.

서비스마다 형식이 다른 행동 기록을 먼저 공통 형식으로 변환한 뒤 사용자 상태를 계산합니다. 새 서비스를 연결할 때는 그 서비스용 변환기만 추가하면 되고, 상태 계산 코드는 수정하지 않습니다.

회사별 데이터 분리

같은 회사가 운영하는 여러 앱은 사용자 상태를 함께 사용하고, 다른 회사의 사용자 데이터와는 섞이지 않도록 분리했습니다.

추천 엔진에서 행동 분석 서버로 옮긴 순서

  1. 범위 확인옮길 코드와 남길 코드 사이에 참조가 없는지 확인
  2. 의존성 제거외부 수치연산 라이브러리를 직접 구현해 교체
  3. 일치 확인무작위 표본과 경계 사례로 전후 결과 비교
  4. 새 서버 먼저 배포기존 API는 유지하고 비활성 상태로 배포
  5. 남은 코드 삭제호출되지 않는 코드를 삭제하고 다시 추가되면 구문 트리 검사로 차단

보드게임 정보 수집 서버

수집기를 설계하고 구현했으며, 수집한 데이터는 보키요의 공통 게임 정보로 사용했습니다.

보드게임 정보, 카드 슬리브 규격, 설명 영상을 세 곳에서 자동으로 수집하는 Spring Boot 서버입니다. 보드요잉 프로토타입 단계에서 만들어 현장에서 시험했고, 이때 수집한 데이터와 데이터 구조를 보키요의 공통 게임 정보로 사용했습니다.

카드 슬리브 규격 수집

  1. 대상 고르기카드 정보가 없는 게임을 ID 순으로 100개씩
  2. 게임 ID 찾기영문 이름으로 슬리브 정보 사이트를 검색
  3. 규격 조회카드 크기, 장수, 게임 요약을 1초 간격으로 요청
  4. 실패 처리요청이 실패하면 60초 대기 후 다음 게임

설명 영상 수집

  1. 100개씩 묶기게임 ID 순서로 한 묶음씩
  2. 영상 검색“게임명 보드게임 설명”으로 YouTube 검색
  3. 상위 3개 저장영상 제목, 링크, 채널 이름
  4. 이어서 수집마지막으로 처리한 ID부터 다음 묶음

보키요에서는 이 영상 목록 중 매장이 고른 영상을 키오스크의 게임 상세 화면에 표시합니다.

한 일

  • 목록의 게임을 하나씩 새 탭으로 열어 이름, 인원, 플레이 시간, 출시일, 평점, 대표 이미지를 수집했습니다. “2-4”처럼 범위로 적힌 인원과 시간은 최솟값과 최댓값으로 나눠 저장했습니다.
  • 디자이너, 아티스트, 메커니즘, 테마는 이름으로 먼저 조회하고 없을 때만 새로 저장한 뒤 ID로 연결해, 같은 이름이 중복 저장되지 않게 했습니다.
  • 대상 사이트에 부담을 주지 않도록 게임마다 5초씩 대기하고, 슬리브 정보 요청이 실패하면 60초 뒤에 이어서 수집했습니다.
  • 설명 영상과 슬리브 규격은 게임 100개 단위로 수집하고, 마지막으로 처리한 ID를 반환해 다음 실행에서 이어서 수집할 수 있게 했습니다.
  • 사이트 화면 구조에 따라 달라지는 CSS 선택자는 상수로 모아, 대상 사이트가 바뀌어도 상수만 수정하면 되도록 했습니다.
  • 개발 DB는 Docker 컨테이너의 PostgreSQL로, 테스트 DB는 H2로 나눠 수집 로직과 저장소를 각각 테스트했습니다. 기능 개발은 브랜치와 PR 단위로 진행했습니다.

외부 변화 영향 판정 엔진

백엔드와 프론트엔드를 혼자 개발했고, 현재 POC 단계를 개발하고 있습니다.

외부 변화가 회사의 손익과 현금흐름에 어떤 경로로 이어지는지 계산하는 엔진입니다. 엔진은 환율 변동, 원자재 가격 변동, 관세 변경, 수출통제 변경, 공급 중단 사건을 같은 그래프 계산으로 처리하고, 첫 적용 사례로 환율 영향 분석을 구현했습니다. 회사가 입력한 통화별 수취와 지급 예정액, 외화 채권과 채무, 헤지 계약을 바탕으로 환율이 3%, 5%, 10% 움직일 때 손익과 현금흐름이 얼마나 바뀌는지 계산하고 원인을 나눠 보여 줍니다. 금리와 그 밖의 규제는 아직 구현하지 않은 확장 방향입니다.

한 일

  • 외부 공개 데이터 수집은 Python 수집 스크립트 18개가 맡고, 서버는 스크립트가 보낸 사건만 받도록 나눴습니다. 서버가 외부 API를 호출하지 않아 계산 결과가 호출 시점의 API 상태에 따라 달라지지 않습니다. 필수 값이 빠진 사건은 그 사건만 보류합니다.
  • 전파 커널은 저장소, 시각, 난수, LLM을 사용하지 않는 순수 함수로 만들었습니다. 위상정렬 순서로 노드를 한 번씩 계산하고, 근거가 부족한 엣지는 이유와 함께 제외한 뒤 나머지 그래프를 계속 계산합니다.
  • 정렬 순서와 반올림 방식에도 버전을 붙여 실행 기록에 저장하고, 실행 시각과 실행자는 해시 입력에서 뺐습니다. 같은 입력을 다시 실행했을 때 같은 해시가 나오는지 확인할 수 있습니다.
  • 사건을 충격의 크기와 기간으로 바꾸는 변환은 서로 독립된 두 방식의 결과가 일치해야 계산에 사용하고, 결과가 다르면 사람이 승인해야 합니다. 자동 검증에 실패한 변환은 저장하지 않습니다.
  • 산업 평균 계수는 관계가 있다는 표시로만 사용하고 계산용 계수로는 쓰지 않았습니다. 계수는 입력된 원가 비중이나 공시에서 확인한 값만 사용합니다.
  • API 키마다 접근할 수 있는 테넌트를 정하고, 키만으로 테넌트를 알 수 없는 자원은 서비스에서 소유 테넌트를 찾은 뒤 컨트롤러에서 다시 확인했습니다. 다른 테넌트의 자원을 요청하면 소유 테넌트가 드러나지 않는 같은 오류 문장으로 거절합니다.
  • 화면은 Next.js로 만들고, 환율 영향 분석, 1페이지 보고서, 경로, 결정, 운영 화면을 구현했습니다.
